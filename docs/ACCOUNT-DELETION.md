# অ্যাকাউন্ট ডিলিট রিকোয়েস্ট সিস্টেম (নতুন)

ইউজাররা এখন প্রোফাইল থেকে সরাসরি অ্যাকাউন্ট ডিলিটের অনুরোধ পাঠাতে পারে — আর সব
অনুরোধ অ্যাডমিন প্যানেলে জমা হয়ে সেখান থেকেই সম্পূর্ণ কন্ট্রোল করা যায়।

## কোথায় কী আছে

### ইউজার সাইড (অ্যাকাউন্ট → নিরাপত্তা ট্যাব)
- "অ্যাকাউন্ট ডিলিটের অনুরোধ" কার্ডে **ডিলিটের অনুরোধ পাঠান** বাটন
- কারণ সিলেক্ট (৫টি প্রি-সেট অপশন) + ঐচ্ছিক বিস্তারিত মেসেজ
- কনফার্মেশন চেকবক্স + নিশ্চিতকরণ ডায়ালগ
- সাবমিটের পরে স্ট্যাটাস কার্ড: পেন্ডিং / প্রসেসিং / সম্পন্ন / বাতিল + অ্যাডমিন নোট
- পেন্ডিং অবস্থায় ইউজার নিজেই অনুরোধ **বাতিল** করতে পারে
- অনুরোধ জমা হলে ইউজার নোটিফিকেশন পায়

### অ্যাডমিন সাইড (অ্যাডমিন প্যানেল → বিক্রয় ও কাস্টমার → ডিলিট রিকোয়েস্ট)
- সেটিংস: ফিচার **চালু/বন্ধ** সুইচ + বন্ধ থাকলে ইউজারকে দেখানো কাস্টম লেখা
- স্ট্যাট কার্ড: পেন্ডিং / প্রসেসিং / সম্পন্ন / বাতিল (ক্লিক করলেই ফিল্টার)
- সার্চ (নাম / ইমেইল / ফোন / কারণ) + স্ট্যাটাস ড্রপডাউন
- নেভিগেশনে পেন্ডিং ব্যাজ (লাল সংখ্যা)
- রো অ্যাকশন: **প্রসেসিং** / **সম্পন্ন** এক ক্লিকে, বিস্তারিত ডায়ালগে স্ট্যাটাস + নোট
- **সম্পন্ন** করার সময় "ব্যক্তিগত ডেটা মুছে ফেলুন" চেকবক্স:
  প্রোফাইল, ঠিকানা, নোটিফিকেশন, টিকেট, লয়ালটি লেজার, রেফারেল ডেটা, পুশ টোকেন
  মুছে যায় — অর্ডার রেকর্ড (হিসাবের জন্য) থেকে যায়, শুধু userId বিচ্ছিন্ন হয়
- রেকর্ড ডিলিট অপশন
- সব পরিবর্তন অডিট লগে থাকে + ইউজার নোটিফিকেশন পায়

## ডেটা কোথায় থাকে
- Firebase RTDB: `shop/deletionRequests` (database.rules.json-এ আলাদা rule লাগে না —
  `shop` নোডের বর্তমান rule-ই কভার করে)
- সেটিংস কী: `deletion_enabled`, `deletion_info_text` (অ্যাডমিন → ডিলিট রিকোয়েস্ট সেকশনে)
